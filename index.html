DEVELOPER GUIDE

Tata Cara Membuat Website Seperti Ini

Panduan panjang dari struktur frontend sampai backend database, autentikasi, role, order, deployment, keamanan, dan realtime.

01

Tentukan arsitektur sejak awal

Pisahkan website menjadi tiga lapisan utama: frontend untuk tampilan, API backend untuk logika server, dan database untuk data permanen. HTML tetap menjadi halaman utama agar desain mudah diedit, sedangkan proses sensitif seperti login, password, role, blacklist, penghapusan user, produk, dan order dilakukan melalui backend.

frontend: index.html
backend: api.php + config.php
database: database.sql / MySQL
02

Siapkan hosting dan database

Gunakan hosting yang mendukung PHP 8+ dan MySQL/MariaDB. Buat database baru, catat host, nama database, username database, dan password database. Jangan menaruh credential database di HTML karena HTML bisa dilihat semua pengunjung.

03

Buat tabel users

Tabel user minimal menyimpan user_id, username, password_hash, role, status, protected, created_at, updated_at, dan last_login_at. Password jangan disimpan sebagai teks biasa. Backend wajib menggunakan password_hash dan password_verify.

04

Buat sistem session token

Setelah login benar, backend membuat token acak yang disimpan pada tabel sessions. Browser hanya menyimpan token session tersebut. Setiap request sensitif mengirim token ke API. Token session memiliki waktu kedaluwarsa sehingga akun tidak terus-menerus aktif tanpa batas.

05

Register username + password

Form register meminta username, password, dan konfirmasi password. Backend memvalidasi panjang serta karakter username, memastikan username unik, membuat User ID, mengenkripsi password menggunakan hashing server, lalu menyimpan akun dengan role USER dan status ACTIVE.

06

Login wajib sebelum membuka aplikasi

Gunakan auth gate sebagai pintu utama. Pengunjung yang belum punya session tidak boleh masuk ke halaman produk, order, profil, developer, maupun halaman lain yang membutuhkan identitas. Setelah login berhasil, frontend meminta state terbaru dari server.

07

Buat role hierarchy

Gunakan minimal tiga role: USER, ADMIN, dan DEVELOPER. USER bisa melihat katalog dan membuat order. ADMIN bisa mengelola order sesuai izin. DEVELOPER mempunyai akses pengelolaan produk, seluruh user, role, blacklist, dan penghapusan akun.

08

Daftar User khusus Developer

Halaman user management harus meminta otorisasi developer di server, bukan hanya menyembunyikan tombol lewat JavaScript. Tampilkan username, User ID, role, status, tanggal dibuat, dan aksi pengelolaan.

09

Angkat dan cabut role

Developer dapat mengubah USER menjadi ADMIN atau DEVELOPER. Sebelum menyimpan, backend mengecek slot maksimal dan memastikan target bukan akun protected. Saat role dikembalikan ke USER, data role lama dibersihkan dan frontend mengambil state baru.

10

Blacklist user

Blacklist sebaiknya mengubah status akun menjadi BLACKLISTED, bukan langsung menghapus data. Saat user mencoba login, backend menolak akses dan memberi pesan yang jelas. Developer dapat mengaktifkan kembali akun tersebut.

11

Hapus user secara permanen

Aksi hapus harus meminta konfirmasi dan dilakukan hanya oleh Developer. Backend wajib mencegah penghapusan akun protected dan akun Developer yang sedang login. Data session milik user yang dihapus ikut dicabut agar token lama tidak dapat digunakan.

12

Tambah Produk

Developer memasukkan nama produk, harga, kategori, WhatsApp penjual, QRIS, dan deskripsi. Setelah disimpan, produk langsung masuk katalog karena katalog membaca data dari endpoint state. Tidak ada tabel atau form order manual tambahan.

13

Jadikan produk sebagai sumber order

Alur yang dipakai adalah Developer menambahkan produk → user memilih produk → sistem membuat pending payment → user membayar → order tercatat → bukti pembayaran dikirim ke WhatsApp → admin/developer memproses status. Ini menjaga satu sumber data produk tanpa form order manual terpisah.

14

Validasi order di backend

Frontend boleh menghitung total untuk tampilan, tetapi backend harus menghitung ulang harga dari database berdasarkan product_id. Jangan percaya harga dari browser karena browser milik user dapat dimodifikasi.

15

Status PENDING dan DONE

Order baru dibuat sebagai PENDING. Setelah pembayaran diperiksa oleh operator, status berubah menjadi DONE. Simpan updated_at dan processed_by agar jejak perubahan mudah ditelusuri.

16

QRIS dan tautan WhatsApp

QRIS dapat memakai URL gambar atau data URL untuk versi sederhana. Untuk deployment skala besar, lebih baik menyimpan gambar pada object storage/CDN dan database hanya menyimpan URL. WhatsApp dapat dibuka menggunakan nomor seller produk yang tersimpan di database.

17

Realtime lintas perangkat

BroadcastChannel hanya membantu sinkronisasi browser yang mendukungnya pada perangkat yang sama. Realtime lintas HP membutuhkan server bersama. Cara paling sederhana adalah frontend melakukan polling berkala ke API; versi lanjut dapat menggunakan WebSocket atau layanan realtime.

18

Keamanan API

Backend harus memvalidasi token session, role, input, panjang string, angka harga, URL HTTPS, dan User ID. Hindari SQL string concatenation; gunakan PDO prepared statements. Atur header Content-Type application/json dan validasi method HTTP.

19

Cegah manipulasi role

Jangan pernah menerima role dari browser lalu langsung mempercayainya. Server harus menentukan role berdasarkan record akun yang sedang login. JavaScript hanya mengatur antarmuka; keputusan izin tetap berada di API.

20

Lindungi akun Developer

Akun Developer utama diberi flag protected. Backend menolak blacklist, penghapusan, atau perubahan role terhadap akun tersebut. Credential Developer sebaiknya diganti setelah deployment dan tidak dibagikan kepada pengguna lain.

21

Deployment struktur file

Upload index.html, api.php, config.php, dan database.sql. Import database.sql ke MySQL. Isi konfigurasi database pada config.php. Setelah itu buka index.html melalui domain hosting, bukan file:// jika API PHP ingin bekerja.

/public_html/index.html
/public_html/api.php
/public_html/config.php
/public_html/database.sql
22

HTTPS wajib

Gunakan HTTPS pada domain website. Jangan mengirim session token melalui HTTP biasa. Aktifkan SSL hosting dan gunakan URL API relatif seperti api.php agar domain frontend dan backend tetap satu origin.

23

Testing sebelum dibuka publik

Uji register, duplicate username, login salah, login benar, logout, blacklist, unblacklist, ubah role, cabut role, delete user, tambah produk, delete produk, buat order, proses DONE, dan akses developer. Uji juga dua HP untuk memastikan state berasal dari database yang sama.

24

Backup database

Karena data sudah disimpan server, lakukan backup MySQL berkala. Backup database berbeda dengan backup HTML. HTML dapat dipulihkan dari file deployment, sedangkan database menyimpan akun, order, produk, dan session.

25

Pengembangan lanjutan

Setelah fondasi ini stabil, sistem dapat ditambah email verification, reset password, 2FA, audit log, dashboard statistik, search user, filter order, pagination, rate limit, CAPTCHA, upload media ke storage, payment gateway, dan notification service.

26

Prinsip paling penting

Tampilan boleh sangat cantik dan penuh animasi, tetapi autentikasi, authorization, password, role, blacklist, dan delete user harus diputuskan oleh backend. Frontend tidak boleh dianggap sebagai batas keamanan.
